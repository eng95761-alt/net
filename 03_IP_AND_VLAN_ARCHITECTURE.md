## 2. VLAN Architecture Audit

### Configuration Review:
- `/interface vlan print detail`: **0 VLANs configured** (Empty).
- `/interface bridge vlan print detail`: **0 Bridge VLAN entries** (Empty).
- Bridge VLAN Filtering: **`vlan-filtering=no`**.

### Architectural Evaluation:
The router employs a **Flat Layer 2 Network Architecture** without IEEE 802.1Q VLAN segmentation. All member ports of `Bridge-Local` (`ether3` through `ether10`) reside within a single broadcast domain (PVID=1).

### Risks of Flat Layer 2 in WISP / Distribution Environments:
1. **Broadcast Storm Propagation:** Broadcast frames (ARP, DHCP discoveries, MNDP, LLDP) generated by any client or radio traverse all bridge ports unimpeded.
2. **Multi-Netting on a Single Bridge:** Four distinct IPv4 subnets (`192.168.0.0/24`, `192.168.1.0/24`, `192.168.2.0/24`, and `192.168.9.0/24`) coexist on the exact same Layer 2 segment. Hosts in different subnets share the broadcast domain, resulting in security exposure and unnecessary CPU packet processing.
3. **Neighbor Discovery Pollution:** Over 1,000 lines of neighbor discovery data were captured from devices on `ether2` and bridge ports, demonstrating widespread Layer 2 transparency across multiple remote towers and customer radios.

## 3. Subnet Anomalies & Configuration Defects

### A. [HIGH-04] Subnet Mask Mismatch: DHCP `/16` vs Interface `/24`
- **Interface Setting:** `address=192.168.0.1/24 interface=Bridge-Local`
- **DHCP Network Setting:** `address=192.168.0.0/16 gateway=192.168.0.1 dns-server=8.8.8.8,1.1.1.1`
- **Technical Analysis:**
  - When DHCP clients (such as `Karbala Mall 3` at `192.168.0.249`) obtain their lease, they configure their netmask as `255.255.0.0` (`/16`).
  - To the client, any IP in the entire `192.168.0.0` – `192.168.255.255` range is considered local (on-link). If the client attempts to reach `192.168.1.15` (which resides on `ether7`), it sends an ARP request directly instead of routing through `192.168.0.1`.
  - Conversely, the router's interface is configured with `/24` (`255.255.255.0`), meaning the router views `192.168.1.0/24` as a separate connected subnet.
  - This asymmetry leads to ARP resolution timeouts, intermittent connectivity, and routing failure for static devices.
- **Remediation:** Align `/ip dhcp-server network` to match `/ip address` (`192.168.0.0/24`).

### B. [MED-02] Overlapping & Problematic IP Pool Definitions
Inspection of `/ip pool` revealed:
1. **Duplicate Local Pools:**
   - `Pool-Local`: `192.168.0.10-192.168.0.250`
   - `Pool-QN-Local`: `192.168.0.10-192.168.0.250`
   - Both pools specify the exact same range.
2. **Invalid Network-Zero Address in PPPoE Pools:**
   - `Pool-PPOE-2M`: `172.16.2.0-172.16.2.254` (Starts at `.0`)
   - `Pool-PPOE-10M`: `172.16.10.0-172.16.10.254` (Starts at `.0`)
   - `Pool-PPOE-unlimeted`: `172.16.100.0-172.16.100.254` (Starts at `.0`)
   - While RouterOS point-to-point PPPoE links technically tolerate `/32` allocations ending in `.0`, many client operating systems (Windows, Linux, Android) reject an IP address ending in `.0` as an invalid network identifier. All other pools (`Pool-QN-*`) properly start at `.1`.
